# Feasibility research, 24 Nov 2026

Free, read-only checks before building: OSV, the npm registry, GitHub, and miner 7314's rules pass run locally with no model and no wallet. Nothing was paid.

## Target repositories (suggested by Telegraph, 24 Nov)

| Repository | npm side | Lockfile | Notes |
| --- | --- | --- | --- |
| `anza-xyz/wallet-adapter` | the whole repo | `pnpm-lock.yaml` v9, pnpm workspace | monorepo |
| `solana-foundation/anchor` | `ts/` (TypeScript client) | `ts/yarn.lock` (Yarn 1, workspaces) | mainly Rust (`Cargo.lock`), out of scope |
| `drift-labs/protocol-v2` | `sdk/` | `sdk/yarn.lock` | mainly Rust (`Cargo.lock`), out of scope |

All three are monorepos or nested packages. The Telegraph PR Agent rejects workspaces because it edits lockfiles; a read-only report can read every workspace member.

## Compromised dependency

`@solana/web3.js` 1.95.6 and 1.95.7 (published 3 Dec 2024) are flagged by OSV as `GHSA-jcxm-7wvp-g6p5` and `MAL-2024-11183` (malware that exfiltrates private keys). npm has removed both versions. None of the three target repositories locks them, so this scenario needs a controlled test repository, labelled as historical.

## Problems found

- `@solana/web3.js`'s full npm registry document is 12 MB and took 8.2 s to download, against the miner's 10 s source limit. The abbreviated form (`Accept: application/vnd.npm.install-v1+json`) is 4.7 MB in 2.9 s. Needs a miner fix.
- `@solana/spl-token`'s npm versions (0.4.x) don't match its repository's tags (`js@v0.20.x`); expect `not_found` from the miner.
- Release notes exist: `@solana/web3.js` and `@solana/kit` (GitHub releases), `@coral-xyz/anchor` (releases and `CHANGELOG.md`), wallet-adapter (per-package release tags).
